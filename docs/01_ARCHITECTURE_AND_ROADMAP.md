# 아키텍처 설계 가이드 & 단계별 구현 로드맵

이 문서는 처음부터 10가지 기능을 한꺼번에 만들다 막히지 않도록, **모듈을 어떻게 나누고 어떤 순서로 직접 코딩하면 좋은지** 안내하는 설계 지도입니다.

---

## 1. 왜 모듈(계층)을 나누어야 할까요?

만약 `main.py` 파일 하나에 `input()`, 파일 읽기/쓰기, 합계 계산, `print()`를 전부 섞어 넣으면 어떤 일이 벌어질까요?
- 나중에 `add`는 대화형(`input`)으로 받고 `import`는 CSV 파일에서 읽어야 할 때, **저장 로직을 똑같이 두 번 복붙**하게 됩니다.
- 저장 포맷을 바꾸거나 수정(`update`) 방식을 바꿀 때 프로그램 전체를 다 뜯어고쳐야 합니다.

그래서 역할을 **4개의 핵심 계층(Layer)**으로 나눕니다.

```text
[ 사용자 / 터미널 ]
       │  명령어 인자 (argparse) / 대화형 입력 (input)
       ▼
┌──────────────────────────────────────────────────────────┐
│ 1. CLI 계층 (cli.py, decorators.py)                      │
│   - 사용자의 입력을 받고 결과를 화면에 예쁘게 출력(print) │
│   - 에러가 발생하면 스택트레이스 대신 [오류]/[힌트] 출력  │
└──────────────────────────────────────────────────────────┘
       │  검증된 요청 전달 / 결과 객체 반환
       ▼
┌──────────────────────────────────────────────────────────┐
│ 2. 서비스 계층 (services.py)                             │
│   - 가계부의 핵심 비즈니스 규칙 처리                      │
│   - "사용 중인 카테고리는 삭제 불가", "월별 요약 계산",   │
│     "예산 초과 여부 판별", "CSV 가져오기/내보내기 조합"    │
└──────────────────────────────────────────────────────────┘
       │  데이터 읽기(yield 스트리밍) / 쓰기 요청
       ▼
┌──────────────────────────────────────────────────────────┐
│ 3. 저장소 계층 (repositories.py)                         │
│   - 파일(JSONL/CSV)을 실제로 열고 닫으며 읽고 쓰는 역할   │
│   - 제너레이터(yield)로 한 줄씩 객체를 꺼내줌             │
│   - 수정/삭제 시 임시 파일을 거쳐 안전하게 덮어쓰기       │
└──────────────────────────────────────────────────────────┘
       │  직렬화(dict/문자열 변환) 및 검증
       ▼
┌──────────────────────────────────────────────────────────┐
│ 4. 도메인 모델 & 검증 계층 (models.py, validators.py, errors.py) │
│   - Transaction, Budget, Category 데이터 구조(@dataclass) │
│   - 날짜/금액/타입 유효성 검사 함수 및 커스텀 예외 클래스 │
└──────────────────────────────────────────────────────────┘
```

### 각 파일에 무엇을 작성하면 될까요?
1. **`errors.py`**: 프로젝트 전용 에러 클래스 (예: `BudgetAppError(message, hint)`). 어디서든 이 에러를 `raise`하면 원인(`message`)과 해결 방법(`hint`)을 함께 담을 수 있습니다.
2. **`validators.py`**: 날짜(`YYYY-MM-DD`), 월(`YYYY-MM`), 양수 금액(`int > 0`), 타입(`income`/`expense`) 등을 검사하고 틀리면 `BudgetAppError`를 발생시키는 순수 함수들입니다.
3. **`models.py`**: `@dataclass`로 만든 `Transaction`, `Budget`, `Category` 클래스입니다. 파일에 저장하기 위해 딕셔너리로 바꾸는 메서드(`to_dict`)와 딕셔너리에서 객체로 복원하는 메서드(`from_dict`)를 함께 두면 편리합니다.
4. **`repositories.py`**: `transactions.jsonl`, `categories.jsonl`, `budgets.jsonl` 파일을 담당하는 저장소 클래스들입니다. 여기서 **`yield`를 이용한 스트리밍 읽기**와 **안전한 파일 저장**을 구현합니다.
5. **`services.py`**: 저장소들을 조합해서 실제 10대 기능(거래 추가, 검색 필터링, 월별 요약, 예산 비교, CSV 입출력)을 수행하는 클래스(예: `BudgetService`)입니다.
6. **`decorators.py`**: CLI 명령이나 서비스 함수를 감싸서 에러가 났을 때 `[오류]`/`[힌트]`를 출력하고 종료 코드를 반환하거나, 실행 시간을 기록하는 데코레이터입니다.
7. **`cli.py` & `__main__.py`**: `argparse`로 명령어(`add`, `list`, `summary` 등)를 정의하고 사용자의 입력을 받아 `services.py`를 호출한 뒤 결과를 출력합니다.

## 2. 손으로 직접 코딩하는 7단계 로드맵

한 단계를 완성할 때마다 터미널에서 직접 실행해 보며 눈으로 결과를 확인하는 순서를 추천합니다.

### Stage 1. 기초 공사: 에러(`errors.py`), 검증(`validators.py`), 데이터 모델(`models.py`)
- **목표**: 가계부 데이터가 어떤 모양인지 정의하고, 잘못된 값을 걸러내는 필터 만들기
- **직접 해볼 것**:
  1. `errors.py`에 `message`와 `hint` 속성을 가진 사용자 정의 예외 클래스 만들기
  2. `validators.py`에 날짜(`datetime.date.fromisoformat` 활용), 월, 금액, 거래 타입 검증 함수 만들기
  3. `models.py`에 `@dataclass`로 `Transaction`(필드 7개), `Budget` 등 정의하고 `to_dict()` / `from_dict()` 작성하기
- **확인 방법**: 파이썬 인터프리터나 간단한 테스트 코드로 `Transaction` 객체를 만들고 딕셔너리로 변환했다가 다시 복원해 보기

### Stage 2. 영구 저장소와 제너레이터: `repositories.py`
- **목표**: 파일 3개(`transactions`, `categories`, `budgets`)를 생성하고, `yield`로 한 줄씩 읽어오기
- **직접 해볼 것**:
  1. 데이터 폴더(`./data`)가 없으면 자동 생성(`pathlib.Path.mkdir`)하는 초기화 로직 작성
  2. 카테고리 저장소(`CategoryRepository` 또는 `CategoryStore`) 만들기 — 초기 실행 시 기본 카테고리를 넣을지 결정
  3. 거래 저장소(`TransactionRepository`) 만들기:
     - 한 건 추가(`append` 모드로 한 줄 쓰기)
     - **핵심**: 파일 전체를 `readlines()`로 읽지 않고, `for line in file:` 루프 안에서 `yield Transaction.from_dict(...)`로 한 건씩 내보내는 제너레이터 메서드 작성
     - 수정(`update`)과 삭제(`delete`)를 위해 전체 스트림을 순회하며 임시 파일에 새로 쓰고 교체하는 메서드 작성
  4. 예산 저장소(`BudgetRepository` 또는 `BudgetStore`) 만들기

### Stage 3. 첫 번째 End-to-End 연결: CLI 뼈대(`cli.py`) + `category` + `add` + `list`
- **목표**: 터미널에서 직접 내역을 추가하고 최신순 목록을 조회해 보기!
- **직접 해볼 것**:
  1. `cli.py`에 `argparse.ArgumentParser`와 `add_subparsers()`로 명령어 틀 잡기
  2. `decorators.py`에 예외 처리 데코레이터를 만들어 에러 발생 시 스택트레이스 대신 `[오류]`/`[힌트]`가 출력되고 종료 코드가 `1`이 되도록 연결하기
  3. `category add / list` 및 대화형 `add`, 스트리밍 기반 `list --limit N` 연결하기
- **생각해볼 포인트**: 파일에는 오래된 순서대로 쌓이는데, `list`에서 **최신순**으로 보여주려면 어떻게 해야 할까요? (저장할 때 정렬할지, 읽을 때 처리할지 고민해 보기)

### Stage 4. 검색(`search`)과 수정/삭제(`update`, `delete`)
- **목표**: 제너레이터 파이프라인으로 조건 필터링하기 & 안전하게 기존 데이터 수정/삭제하기
- **직접 해볼 것**:
  1. `services.py`에서 저장소의 제너레이터를 받아 `--from`, `--to`, `--category`, `--type`, `--q`(메모 키워드), `--tag` 조건에 맞는 거래만 다시 `yield`하는 검색 메서드 작성
  2. `delete --id <id>`와 `update --id <id> ...` 구현 (없는 ID일 때 처리 포함)
  3. `category remove` 구현 시 **해당 카테고리를 사용하는 거래가 하나라도 있는지** 스트리밍으로 확인하고 삭제를 막는 로직 추가

### Stage 5. 예산(`budget`)과 월별 요약(`summary`)
- **목표**: 특정 월(`YYYY-MM`)의 데이터를 스트리밍으로 집계하고 예산 사용률 계산하기
- **직접 해볼 것**:
  1. `budget set --month YYYY-MM --amount 금액` 구현
  2. `summary --month YYYY-MM --top N` 구현:
     - 해당 월의 총수입, 총지출, 잔액(`총수입 - 총지출`) 계산
     - 카테고리별 지출 합계를 딕셔너리에 모은 뒤 상위 `N`개 정렬(`sorted(..., key=..., reverse=True)[:top_n]`)
     - 설정된 예산이 있다면 사용률(`총지출 / 예산 * 100`)과 예산 초과 경고 문구 출력
     - 해당 월에 거래 내역이 0건이면 `"데이터 없음"` 명확히 출력

### Stage 6. CSV 가져오기/내보내기 (`import`, `export`)
- **목표**: 외부 CSV 파일과 가계부 데이터를 주고받기 (`csv.DictReader`, `csv.DictWriter`)
- **직접 해볼 것**:
  1. `export --out <csv>` + (`--month` 또는 `--from`/`--to` 필수 검증): 조건에 맞는 거래를 `date,type,category,amount,memo,tags` 컬럼 순서로 저장
  2. `import --from <csv>`: 각 행을 읽어 유효성을 검사하고, 성공 건수(`imported`)와 실패/건너뛴 건수(`skipped`) 출력

### Stage 7. 마무리 점검 및 `README.md` 작성 (선택: 보너스 과제)
- **목표**: 요구사항 체크리스트 최종 점검 및 문서 완성
- **직접 해볼 것**:
  1. 모든 명령어에 `--help`가 잘 나오는지, 에러 시 스택트레이스가 안 나오고 종료 코드가 0이 아닌지 확인
  2. `README.md`에 실행 방법, 저장 파일 위치/형식, 주요 명령 예시, CSV 스키마 문서화
  3. 여유가 있다면 보너스 과제(백업, 반복 내역, 테이블 정렬, 원자적 교체 심화) 도전!
